# My_CTF_portal

社内CTF向けのツールポータルです。HTML + JavaScript だけで動く静的サイトなので、GitHub Pages でそのまま公開できます。
入力した内容はすべてブラウザ内で処理され、外部には送信されません。

## 機能

ホーム画面の中央にあるコマンドバーに問題の文字列を貼ると、その場で正体を推理して使うツールを提示します（Enter で最有力のツールを開きます）。ファイルはホームのどこにドロップしてもファイル解析に送られます。

## 初心者向けの工夫

- 各ツールの上に「使い方・こんなときに使う」パネルがあり、**「▶ 例を試す」でサンプル問題を読み込めます**（触りながら使い方を覚えられます）
- 「迷ったら診断」の結果から、そのままツールに中身を渡して開けます（エンコードなら Magic、RSA なら自動で解くところまで実行）
- 使い方パネルは開閉でき、閉じた状態は全ページで記憶されます（慣れた人は閉じておけます）

## 見た目の切り替え

- 右上の **☾ / ☀ ボタン**でダーク / ライトを切り替えます（選んだものはブラウザに保存）
- 右上の **CYAN / CRIMSON / EMERALD** でアクセントカラーを切り替えます。ライトモードでは、白地でも読みやすいよう少し深い色になります

## 案内役 PALLAS（パラス）

画面を飛び回る作戦支援ドローン。冷静で頭が切れて、ときどき皮肉を言う頼れる相棒です（初心者をけなすことはしません）。

- **飛び回る**：ばね式の物理演算でなめらかに飛び、進む方向へ機体を傾けます。操作が落ち着くと、画面の空いている場所を巡回します（吹き出しの「自由に飛び回る」でオフ）
- **ドラッグで移動**：好きな場所に置くと、そこが新しい定位置になります（メニューの「定位置に戻る」で元に戻せます）
- **現場へ飛ぶ**：ツアーでは説明する部品の横へ、フラグ発見などの出来事では結果の横へ飛んでいき、必要ならスクロールもします
- **初回ツアー**：ページを回りながら部品を光らせて説明します
- **ページ案内**：ブラウザを開くたびに、各ページを最初に開いたとき1回だけひとこと案内します（同じセッション内では繰り返しません。「ページごとに案内」でオフ）
- **反応**：フラグ発見（Magic・ファイル解析・RSA）、怪しいデータ、PNG の復元、問題の解決、通信断、テーマ変更、連続タップなどに、場面ごとに複数パターンのセリフで反応します。フラグはそのまま「問題メモに記録」できます
- **ひとりごと**：しばらく操作が無いと、たまに話しかけてきます。深夜はあいさつも変わります
- マウスやタップの方向を見て、カラーテーマに合わせて発光色が変わります。「隠れる」で小さなチップにしまえます

3D 表示は three.js（`vendor/three/`、MIT ライセンス）で、モデルは `models/pallas_drone.glb` です。オフラインでも表示され、WebGL が使えない環境ではアイコン表示になります。モデルにアニメーションは含まれていないため、浮遊・シールド板の周回・ヒレのはばたき・目の発光・移動中の傾きなどは `js/ui/pallas3d.js` で動かしています。セリフは `js/data/pallas.js` で編集できます。

## アプリとしてインストール（PWA）

ホーム画面やデスクトップにインストールでき、**一度開けばオフラインでも全ツールが動きます**（会場のネットワークが不安定でも使えます）。

- **PC（Chrome / Edge）**：右上の「INSTALL」ボタン、またはアドレスバーのインストールアイコン
- **Android（Chrome）**：メニュー →「ホーム画面に追加」/「アプリをインストール」
- **iPhone / iPad（Safari）**：共有ボタン →「ホーム画面に追加」

新しいバージョンを公開すると、画面下に「新しいバージョンがあります」と表示されます。「更新する」を押すと切り替わります。

仕組み：デプロイ時に `scripts/build-sw.mjs` が公開ファイルの一覧とビルドID（コミットSHA）を `sw.js` に埋め込みます。逆アセンブラ（Capstone、約 3.6MB）はインストール時に、OCR のエンジンとモデル（onnxruntime-web と PaddleOCR、約 34MB）は初めて使ったときに、それぞれ専用キャッシュへ保存します（以後はオフラインでも動作し、アプリを更新しても再ダウンロードしません）。ローカル開発時（ビルドID が `dev`）はネットワーク優先で動くので、キャッシュに邪魔されずに編集を確認できます。

## GitHub Pages での公開

GitHub Actions（`.github/workflows/pages.yml`）で自動公開します。

1. このリポジトリの **Settings → Pages** を開き、**Build and deployment** の Source を「**GitHub Actions**」にする（最初の1回だけ）
2. `main` ブランチに push すると、テスト → 公開が自動で実行されます
   - **Actions** タブの「Deploy to GitHub Pages」から「Run workflow」で手動実行もできます
3. 公開先: `https://<ユーザー名>.github.io/My_CTF_portal/`

テストが失敗した場合は公開されません。公開されるのは `index.html` / `manifest.webmanifest` / `sw.js` / `css` / `js` / `icons` / `vendor`（three.js・jsQR・Capstone.js・onnxruntime-web・PaddleOCR のモデル）/ `models` だけで、テストや README は含まれません。

## ローカルで動かす

ES Modules を使っているため、`index.html` を直接開くのではなく簡易サーバー経由で開いてください。

```sh
python3 -m http.server 8000
# http://localhost:8000 を開く
```

## テスト

```sh
node tests/run.mjs
```

## 構成

```
index.html          画面
manifest.webmanifest / sw.js / icons/   PWA（インストール・オフライン対応）
scripts/build-sw.mjs  デプロイ時に Service Worker へキャッシュ対象を埋め込む
css/style.css       スタイル（ダーク / ライト × 3色）
js/app.js           起動とページ切り替え
js/ui/              各画面の動作
js/lib/             変換・暗号・ファイル解析などの処理（画面に依存しない関数）
js/data/genres.js   ジャンル定義とチートシートのデータ
tests/run.mjs       処理部分のテスト
tests/fixtures/     テスト用の実行ファイル（crackme.c とそのビルド結果、PE のサンプル）
```

チートシートの項目は `js/data/genres.js` を編集すれば追加できます。
